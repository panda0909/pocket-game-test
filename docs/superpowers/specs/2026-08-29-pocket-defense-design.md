# 《口袋守衛戰》設計規格

日期：2026-08-29
引擎：Godot 4.7.2 stable（`~/Downloads/Godot.app`）
目標平台：網頁 HTML5（開發期以桌面視窗測試）
參考作品：《同盟塔防戰－並肩作戰》（英文名 Coop TD: Together，App Store id6503702666）

## 目的

做一款以「口袋」品牌吉祥物為主角的隨機合成塔防網頁遊戲。參考作品是合作型隨機合成塔防：玩家隨機召喚單位、把同階單位合成升級、抵擋一波波沿軌道前進的敵人。

## 從參考作品擷取與捨棄的部分

參考作品是完整營運中的商業手遊，含合作連線、公會、抽卡、季票、皮膚、寶石合成、文物突破、多難度分支與排行榜。那是多個獨立子系統的集合，不是單一專案的範圍。

**擷取**：隨機召喚、同階合成升級且種類隨機、單位自動攻擊、沿軌道前進的敵人波次、金幣經濟、生命值。這是整個類型的核心循環。

**捨棄**：所有連線與社群功能、所有變現系統、局外養成（寶石／文物／研究所）、多難度分支。

## 遊戲概念

三隻口袋吉祥物守護金庫，抵擋一波波前來行竊的小偷。玩家花金幣在格子上隨機召喚守衛，守衛自動攻擊軌道上的小偷；把兩隻同階守衛拖在一起可合成為高一階、種類隨機的守衛。小偷抵達金庫會偷走生命，歸零即結束。無限波次，記錄最高波數。

## 核心循環

1. 開場畫面顯示標題、最高波次紀錄與「開始」按鈕。
2. 玩家按下「召喚」，花金幣在空格上生成一隻隨機種類的一階守衛。
3. 波次開始，小偷從軌道起點依序進場，沿軌道前進。
4. 守衛自動攻擊射程內的小偷；擊殺獲得金幣。
5. 玩家可拖曳守衛：拖到空格是移動，拖到同階守衛是合成，拖到不同階守衛是交換位置。
6. 小偷抵達軌道終點的金庫，扣除生命並消失。
7. 一波清空後結算金幣，短暫間隔後進入下一波。
8. 生命歸零則結束，顯示本次波數與最高紀錄，可重來。

## 版面與座標

視窗 720×1280 直式，縮放模式 `canvas_items`、長寬比 `keep`。這兩個設定沿用前作的結論：`expand` 會讓遊戲區域隨視窗變形，導致邊界與固定軌道座標失效。

```
┌──────────────────────────┐  y=0
│  波次 3   生命 18   金幣 42 │  HUD
├──────────────────────────┤  y=180
│ ◉入口                 入口◉ │  y=290
│   ╲   ┌────┬────┬────┬────┐ │
│    ╲  │    │    │    │    │ │  y=385
│     ╲ ├────┼────┼────┼────┤ │  y=545
│      ╳│    │    │    │    │ │  中央匯流點
│     ╱ └────┴────┴────┴────┘ │  y=785
│    ╱          ▣金庫         │  y=980
├──────────────────────────┤
│      [ 召喚 · 20 金幣 ]    │  y=1080
└──────────────────────────┘  y=1280
```

**軌道**是左右雙入口的 T／Y 型匯流防線：左路由 `(64, 290)` 進場，右路由 `(656, 290)` 進場，兩路在中央 `(360, 620)` 匯合，最後沿中央通道抵達下方 `(360, 980)` 的金庫。小偷左右交替生成，中央匯流點是高階輸出的主要卡位區。

**守衛格**為 4 欄 × 3 列，共 12 格；格子邊長 116，中心座標列在 `scripts/board.gd` 的 `CELL_POSITIONS`。上下兩排之間保留中央匯流空間，避免單位牆把路徑資訊蓋掉。

左右格與中央附近的格子各自覆蓋不同入口與匯流段；中央匯流點不放守衛格，讓玩家必須在「入口火力」與「匯流火力」之間取捨。這個位置差異是地圖深度的第一層，合成則是第二層。

## 守衛

三個種類，各有明確的戰術定位：

| 種類 | 貼圖 | 定位 | 一階傷害 | 攻擊間隔 | 一階射程 | 特性 |
|---|---|---|---|---|---|---|
| 紅牛 | `red_bull.png` | 單體重擊 | 12 | 1.2 s | 340 | 對高血量單體最有效率 |
| 橘壁虎 | `gecko.png` | 連射 | 4 | 0.35 s | 320 | 穩定輸出，對快腿小偷好用 |
| 綠恐龍 | `dino.png` | 範圍濺射 | 7 | 1.0 s | 330 | 命中點半徑 70 內全體受傷 |

階級 1 到 7。升階時：

- 傷害 × `2.4^(階級-1)`
- 射程 + `15 × (階級-1)`
- 攻擊間隔不變

倍率取 2.4 而非 2 是關鍵：合成一隻高階要消耗兩隻低階，若倍率只有 2，合成就只是把兩格併成一格而沒有變強。2.4 讓「每一格的戰力」隨階級明顯上升，玩家才有動機在格子有限時去合成。七階守衛的傷害是一階的約 191 倍，而它消耗了 64 隻一階，換算下來每格戰力約三倍——合成划算但不至於失衡。

視覺上同一隻吉祥物貼圖，尺寸隨階級微幅放大，外圈顏色與星數標示階級。

## 合成規則

拖曳守衛 A 到守衛 B：

- B 是空格 → A 移動過去
- B 與 A **同階**且兩者皆未達七階 → 兩者消失，該格產生一隻 **階級 +1、種類三選一隨機** 的守衛
- B 與 A 不同階，或任一方已達七階 → 兩者交換位置

種類隨機是參考作品的核心樂趣：你得一邊應對手上拿到的牌、一邊規劃防線。可預測的合成會讓遊戲變成單純的數值累積。

## 敵人

| 種類 | 基礎生命 | 速度 | 偷取生命 | 出現時機 |
|---|---|---|---|---|
| 小偷 | 30 | 60 px/s | 1 | 每波 |
| 快腿小偷 | 18 | 110 px/s | 1 | 第 3 波起 |
| 壯漢小偷 | 90 | 40 px/s | 1 | 第 6 波起 |
| 大盜 | 400 | 45 px/s | 3 | 每 5 波一次 |

生命值隨波次成長：實際生命 = 基礎生命 × `1.28^(波次-1)`。

## 經濟

| 項目 | 公式 |
|---|---|
| 起始金幣 | 60 |
| 召喚費用 | `20 + 4 × 本局已召喚次數` |
| 擊殺獎勵 | `2 + floor(波次 / 3)` |
| 過關獎勵 | `10 + 2 × 波次` |
| 起始生命 | 20 |

召喚費用單調遞增且不重置，這是整個遊戲的難度旋鈕——它決定玩家能鋪多少單位、什麼時候必須靠合成而非數量。所有數值集中在 `scripts/economy.gd` 一處，方便試玩後調整。

## 為可測試性而設計

這款遊戲的規則遠比前作複雜，且**帶有隨機性**。若讓規則散落在節點裡，測試會變成不可能的任務。因此所有規則抽成不繼承 `Node` 的純類別，放在 `scripts/`：

| 檔案 | 職責 |
|---|---|
| `scripts/board.gd` | 格子佔位、放置、移動、交換、合成合法性判定 |
| `scripts/merge_rules.gd` | 合成結果（階級與隨機種類） |
| `scripts/unit_stats.gd` | 依種類與階級算出傷害、射程、攻擊間隔 |
| `scripts/economy.gd` | 召喚費用、擊殺與過關獎勵、金幣收支 |
| `scripts/wave_table.gd` | 每一波的敵人組成與生命值 |
| `scripts/targeting.gd` | 從候選敵人中挑選攻擊目標 |

**亂數必須可注入。** 這些類別接受外部傳入的 `RandomNumberGenerator`，測試時給定固定種子即可穩定重現。隨機玩法若不先處理好這件事，之後每個牽涉隨機的測試都會變成間歇性失敗，而且事後補救要動到所有呼叫端。

節點腳本只負責畫面與輸入：讀取拖曳、呼叫上述類別、更新顯示。

## 資料流

跨節點溝通一律用訊號，方向固定由子節點往上送給 `Main`。

- `HUD` 按下召喚 → 發出 `summon_requested` → `Main` 檢查金幣並委由 `Board` 找空格
- `BoardView` 完成拖放 → 發出 `unit_dropped(from_cell, to_cell)` → `Main` 呼叫 `Board` 判定移動／合成／交換
- `Enemy` 死亡 → 發出 `died(reward)` → `Main` 加金幣
- `Enemy` 抵達金庫 → 發出 `reached_vault(steal)` → `Main` 扣生命
- `Main` 狀態變動 → 呼叫 `hud.update_*()`

`Board`（純資料）是唯一的棋盤真相來源，`BoardView` 只負責把它畫出來。兩者分離之後，所有棋盤規則都能在沒有場景樹的情況下測試。

## 錯誤處理

- 敵人與投射物離開畫面或目標消失時自我回收，並設存活時間上限作為保險。前作證實只靠 `VisibleOnScreenNotifier2D` 不夠：物件若從未進入畫面就不會觸發 `screen_exited`。
- 投射物飛行中目標可能已死亡，命中結算前必須以 `is_instance_valid()` 檢查。
- 召喚時若無空格，拒絕並提示，不扣金幣。
- 金幣不足時召喚鈕呈現停用狀態，避免玩家誤按。
- 遊戲結束時停止所有計時器並清空場上敵人與投射物，避免結束畫面背景仍在跑。
- 拖曳中若收到沒有按鍵的滑鼠移動事件，視為放開事件遺失並結束拖曳。這是前作實際遇到的 bug：玩家把滑鼠拖出視窗外才放開時，角色會永遠跟著游標。

## 測試策略

沿用前作建立的三層驗證，工具直接複製過來：

1. **語法檢查** — 對所有 `.gd` 執行 `--check-only`
2. **單元測試** — GUT 9.7.1，針對 `scripts/` 下六個純類別
3. **整合測試** — 載入主場景，驗證輸入路由、訊號串接、拖曳合成、波次流程

`tools/run_tests.sh` 會比對「GUT 實際載入的測試檔數」與「磁碟上的測試檔數」，擋下 GUT 靜默略過剖析失敗檔案的行為。`tools/verify_game.sh` 依序跑完三層。`tools/capture.tscn` 可在無視窗情況下擷取畫面。

單元測試須涵蓋的重點：

- `Board`：放置到空格、找不到空格、移動、交換、合成合法性（同階可合、異階不可合、七階不可合）
- `MergeRules`：合成後階級正確、種類落在三種之內、固定種子下結果可重現
- `UnitStats`：階級倍率正確、七階數值符合預期
- `Economy`：召喚費用遞增、金幣不足判定、獎勵公式
- `WaveTable`：敵人種類依波次解鎖、生命值成長曲線
- `Targeting`：射程外不選、多個候選時的選擇規則、候選為空時回傳 null
